司雅博的JavaScript —— JSON 展示

JSON（JavaScript Object Notation）是一种轻量级的数据交换格式：长得像 JS 对象，本质是"字符串"，是前后端传数据的通用语言

AJSON 的六种值类型
1合法的值
"字符串" 双引号 20 数字 true / false 布尔 null 空 { } 对象 [ ] 数组
一个合法的 JSON 顶层只能是这六种之一，最常用的是对象和数组；键名必须用双引号包住。
2一个典型的 JSON
对象套数组、数组套对象都很常见；注意没有注释、没有尾逗号、键全部双引号。
3常见错误对照
✗ {name: "司雅博"}
✓ {"name": "司雅博"}
✗ {'age': 20,}
✓ {"age": 20}
✗ {"fn": function(){}}
✓ {"score": null}
键不能用单引号或裸键名；不能有尾逗号；不能放函数、undefined、注释。
BJSON.parse 与 JSON.stringify（互转）
4JSON.stringify：对象 → JSON 字符串
var syb_stu = { name: "司雅博", age: 20, skills: ["HTML", "CSS", "JS"], phone: null }; var syb_text = JSON.stringify(syb_stu, null, 4);
序列化结果：
第 2 个参数是过滤器（常用 null），第 3 个参数是缩进空格数，用来"美化"输出。
5JSON.parse：JSON 字符串 → 对象
var syb_obj = JSON.parse(syb_text); syb_obj.skills[0]; // "HTML"
parse 之后就能像普通对象一样访问：skills[0] = ，age + 1 =
parse 会严格按 JSON 语法检查字符串，不合法会直接抛错（所以常配 try...catch）。
6stringify 会"丢弃"的东西
JSON.stringify({ a: undefined, // 丢失 b: function () {}, // 丢失 c: new Date(), // 变成字符串 d: NaN, e: Infinity // 变成 null });
结果：
undefined 和函数会被直接删掉，NaN / Infinity 变成 null —— 这是序列化的隐藏坑。

记忆口诀：stringify 是"打包发货"（对象 → 字符串），parse 是"签收拆包"（字符串 → 对象）。 JSON 三条铁律：键名双引号、不许写注释和尾逗号、值只有六种。前端所有接口数据（fetch / ajax 返回）几乎都是 JSON， 所以 JSON.parse + JSON.stringify 是最常用的两个全局方法。
